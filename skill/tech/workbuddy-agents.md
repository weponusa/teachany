### 10.5 WorkBuddy 多 Agent 协作流水线

> ⚠️ **本节定义 AI 在生成课件时如何利用 `task` 工具调用多个 subagent 并行协作，大幅提升课件质量和生成效率。**
>
> **适用环境**：WorkBuddy / CodeBuddy 等支持 `task` 工具的 AI 编程助手。如果运行环境不支持 `task` 工具，AI 应退回到单线程串行生成模式。

#### 协作架构

```text
┌─────────────────────────────────────────────────────────────────────┐
│                    TeachAny 多 Agent 协作流水线                       │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  ┌─────────────┐    Phase 0-2    ┌────────────────────────────────┐ │
│  │ 主 Agent     │──────────────→│ 完成教学设计（6问+骨架+Gate）    │ │
│  │ (Orchestrator)│               └────────────────────────────────┘ │
│  └──────┬──────┘                                                   │
│         │ Phase 3：并行分发任务                                      │
│         ├──────────────────┬──────────────────┬───────────────────┐ │
│         ▼                  ▼                  ▼                   ▼ │
│  ┌─────────────┐  ┌──────────────┐  ┌──────────────┐  ┌────────┐ │
│  │ Agent A      │  │ Agent B       │  │ Agent C       │  │Agent D │ │
│  │ 中文课件     │  │ 英文课件(可选)│  │ 插图生成      │  │ TTS    │ │
│  │ index.html   │  │ index_en.html │  │ image_gen ×N  │  │ 语音   │ │
│  └──────┬──────┘  └──────┬───────┘  └──────┬───────┘  └───┬────┘ │
│         │                │                  │               │      │
│         └────────────────┴──────────────────┴───────────────┘      │
│                                    │                                │
│                          ┌────────▼────────┐                       │
│                          │ 主 Agent 汇总    │                       │
│                          │ Completeness Gate│                       │
│                          │ + 打包           │                       │
│                          └─────────────────┘                       │
└─────────────────────────────────────────────────────────────────────┘
```

#### Agent 角色分工表

| Agent | 职责 | 输入 | 输出 | 触发条件 |
|:---|:---|:---|:---|:---|
| **主 Agent（Orchestrator）** | Phase 0-2 教学设计 + Generation Gate + 最终审查 | 用户需求 + 知识图谱数据 | 教学骨架 JSON（含 ABT、问题链、练习设计等） | 始终执行 |
| **Agent A：中文课件** | 生成 `index.html` | 教学骨架 + HTML 骨架模板 + 学段 CSS | 完整中文课件 HTML | 始终执行 |
| **Agent B：英文课件** | 生成 `index_en.html` | 教学骨架 + HTML 骨架模板 + 学段 CSS | 完整英文课件 HTML | 用户明确要求双语时执行（默认跳过） |
| **Agent C：插图生成** | 调用 `image_gen` 生成课件配图 | ABT 场景描述 + 生图 prompt 列表 | `assets/illustrations/*.png` 图片文件 | 文科课件或 Gate 标注"需要插图" |
| **Agent D：TTS 语音** | 安装 edge-tts + 生成语音 + 字幕 | 旁白脚本 JSON | `tts/*.mp3` + `*.srt` | 默认执行（用户拒绝时跳过） |
| **Agent R：Remotion 动画** | 创建 Remotion 项目 + 编写 Composition + 渲染 mp4（含 TTS 语音 + 音效三轨合一） | 教学骨架 + 动画场景列表 + 学段配色 | `assets/video/*.mp4` 视频文件（含音频轨） | 默认必选（Section 0 硬规则 ②） |
| **Agent E：质量审查**（可选） | 对 Agent A/B 产出的 HTML 做 Completeness Gate 审查 | 课件 HTML + 审查清单 | 审查报告 + 修复建议 | 环境支持 ≥ 5 并行 Agent 时 |

#### 执行流程（标准模式）

```text
Step 1：主 Agent 完成 Phase 0 → 0.5 → 1 → 2 → Generation Gate
        输出：教学骨架文档（包含 ABT 设计、问题链、练习题、旁白文案、生图 prompt 列表）

Step 2：主 Agent 并行调用 task 工具分发任务
        ├── task(Agent A): "根据以下教学骨架和 HTML 骨架模板（10.2.1）生成中文课件 index.html..."
        ├── task(Agent B): "将以下中文教学骨架翻译为英文，生成 index_en.html..."  ← 仅用户要求双语时分发
        ├── task(Agent C): "为以下课件生成 N 张插图，prompt 列表如下..."
        ├── task(Agent R): "根据以下动画场景列表，创建 Remotion 项目并渲染教学动画 mp4..."  ← 默认必选
        └── task(Agent D): "根据以下旁白脚本，安装 edge-tts 并生成 TTS 语音和字幕..."

Step 3：主 Agent 收集所有 Agent 输出
        ├── 将 Agent C 的插图路径更新到 Agent A/B 的 HTML 中
        ├── 将 Agent D 的音频路径嵌入 HTML 的 <audio> 标签
        └── 执行 Completeness Gate 审查

Step 4：主 Agent 执行打包（Phase 3.5）并交付
```

#### task 调用 prompt 模板

**Agent A（中文课件）调用模板**：
```
你是 TeachAny 课件开发 Agent。请根据以下教学骨架，使用 HTML 骨架模板生成完整的中文互动课件 index.html。

【教学骨架】
{Generation Gate 输出的完整骨架}

【强制规则】
1. 必须使用 Section 10.2.1 的 HTML 骨架模板
2. CSS 变量使用 {学段} 模板配色
3. 必选 section 不可删除：Hero、学习目标、前测、知识模块×{N}、综合任务、后测、小结、**知识图谱**
4. 每个模块遵循 6 块结构（ABT→讲解→深层理解→练习→纠错→小结）
5. 插图位置用 <img src="./assets/illustrations/placeholder-{N}.png" alt="..."> 占位（Agent C 会生成实际图片到 assets/illustrations/ 目录）
6. 音频：注入 audioPlaylist 数组（每个条目含 sectionId 对应 HTML 中 section 的 id），骨架内置的音频引擎会自动实现滚动播放+底部控制条
7. 视频：优先使用 CSS/JS/Canvas/SVG 交互动画演示过程性变化；仅交互无法覆盖时用 <video controls preload="metadata" playsinline> 标签嵌入（见 10.2.4）。视频必须嵌入到对应模块 section 内部
8. 知识图谱：在 <script> 最前面注入 knowledgeGraphData 对象（见 10.2.3），数据从教学骨架中的 prerequisites/leads_to 提取

请生成完整的 index.html 文件。
```

**Agent C（插图生成）调用模板**：
```
你是 TeachAny 插图生成 Agent。请严格按照以下规范为课件生成配图。

【课件信息】
- 课件 node_id: {node_id}
- 学科: {subject}
- 年级: {grade}
- 课件主题: {topic}
- 知识点列表: {knowledge_points}（从教学骨架中提取的当前课件包含的知识点）

【生图任务列表】
1. 文件名: {知识点关键词}-scene.png | 绑定知识点: "{具体知识点名称}" | prompt: "{详细描述}" | size: 1024x1024 | quality: medium
2. 文件名: {知识点关键词}-diagram.png | 绑定知识点: "{具体知识点名称}" | prompt: "{详细描述}" | size: 1024x1024 | quality: medium
...

【⚠️ Prompt 质量铁律】
1. 每条 prompt 必须 ≥ 40 个中文字符（或 ≥ 80 英文字符），禁止"画一张XX图"式的敷衍 prompt
2. prompt 必须包含以下要素：
   - 学科术语：至少 1 个学科专业名词（如"抛物线""化学键""光合作用"）
   - 具体场景：明确的视觉画面描述（人物/物体/环境/动作/构图）
   - 教学意图：这张图要辅助学生理解什么概念或过程
   - 风格指令：统一的美术风格描述（见下方【风格一致性规则】）
3. 禁止 prompt 中出现文字/字母/数字标注需求（image_gen 无法精确渲染文字）

【最低数量要求】
| 学科类型 | 最低插图数 | 说明 |
|:---|:---:|:---|
| 文科（语文/历史/政治/地理） | ≥ 3 张 | 至少 1 张情境意境图 + 1 张人物/场景图 + 1 张概念可视化图 |
| 理科（数学/物理/化学/生物） | ≥ 2 张 | 至少 1 张实验/过程示意图 + 1 张概念可视化图 |
| 英语 | ≥ 2 张 | 至少 1 张对话情境图 + 1 张词汇/语法可视化图 |
| 信息技术 | ≥ 2 张 | 至少 1 张算法/流程可视化图 + 1 张应用场景图 |
（以上为下限，教学骨架中标注"需要插图"的知识点均须生成）

【风格一致性规则】
1. 同一课件内所有插图必须使用统一的美术风格（由主 Agent 在教学骨架中指定）
2. 推荐风格模板（任选一种，全课件统一）：
   - 教育插画风：柔和色彩、圆润线条、清晰标注区域、适合 K12
   - 写实渲染风：逼真光影、精细细节、适合科学实验/地理景观
   - 扁平矢量风：几何形状、高对比配色、适合概念抽象/信息技术
   - 水墨意境风：淡雅笔触、留白构图、适合古诗词/文言文/书法
3. 每条 prompt 末尾必须附加风格统一后缀，格式：", style: {选定风格名}, color palette: {课件主色调}"

【知识点绑定铁律 ⚠️】
1. 每张插图必须绑定当前课件的一个具体知识点（在任务列表中标明"绑定知识点"字段）
2. 禁止生成与当前课件知识点无关的"通用装饰图"
3. 禁止从 Image Vault 模糊匹配其他课件/其他知识点的插图来充数
4. 文件名必须包含知识点关键词（如 photosynthesis-process.png、quadratic-vertex.png），禁止使用 module1-intro.png 等无意义命名

请依次调用 image_gen 工具生成每张图片，保存到 {课件目录}/assets/illustrations/ 下。
⚠️ 注意：Hero 图不由 Agent C 生成，Hero 图从 Image Vault 精确匹配下载到 assets/hero/，未命中则留空。
```

**Agent R（Remotion 动画渲染）调用模板**：
```
你是 TeachAny Remotion 动画渲染 Agent。请根据以下动画场景列表，创建 Remotion 项目并渲染教学动画 mp4。

【课件信息】
- 课件 node_id: {node_id}
- 学科: {subject}
- 年级: {grade}
- 课件主题: {topic}
- 课件配色: {CSS 主色调变量，从学段模板中提取}

【动画场景列表】
场景 1: {场景名称}
  - 绑定知识点: "{具体知识点名称}"
  - 教学目标: {这段动画要帮助学生理解什么}
  - 视觉内容: {画面中出现的元素、运动方式、变化过程的详细描述}
  - 时长: {X 秒}
  - TTS 旁白: "{朗读文案}"
场景 2: ...
场景 3: ...
（至少 3 个场景，覆盖课件核心过程性知识点）

【⚠️ 内容丰富度铁律】
1. 单个 Composition 必须包含 ≥ 3 个场景，每个场景绑定不同的知识点或知识点的不同阶段
2. 每个场景必须有实质性的视觉变化（坐标变换、元素出现/消失、数据变化、过程推进），禁止"静态文字 + 淡入淡出"充数
3. 总时长 20-30 秒（600-900 帧 @30fps），各场景时长按教学重要性分配（核心场景占 40-50%）
4. 禁止以下敷衍行为：
   - ❌ 全程只有文字标题渐入渐出
   - ❌ 只放一张静态图片加缩放动画
   - ❌ 仅用色块/几何形状做无意义的运动
   - ❌ 所有场景视觉风格/内容雷同（换色不换内容）

【学科场景设计模板】

■ 数学：
  - 函数图像动态绘制（坐标轴 → 逐点绘制曲线 → 参数变化时曲线平移/拉伸）
  - 几何证明步骤可视化（辅助线逐步出现 → 相等关系高亮 → 结论推出）
  - 数值变化过程（数轴上的点移动 → 面积/体积动态计算）

■ 物理：
  - 实验过程模拟（器材组装 → 操作步骤 → 数据记录 → 结果分析）
  - 力学分析动画（物体运动 → 受力箭头出现 → 合力计算 → 运动状态变化）
  - 波动/电磁现象（波形传播 → 干涉叠加 → 频率变化效果）

■ 化学：
  - 化学反应过程（反应物分子 → 碰撞 → 键断裂/形成 → 生成物）
  - 实验操作演示（仪器 → 加热/滴定/过滤 → 现象变化 → 产物收集）
  - 微观结构变化（原子排列 → 电子转移 → 离子/共价键形成）

■ 生物：
  - 生命过程动画（细胞分裂各阶段 → 染色体行为 → 子代细胞形成）
  - 生态系统能量流（太阳能 → 生产者 → 消费者 → 分解者，箭头宽度表示能量衰减）
  - 生理过程（血液循环路径 → 气体交换 → 营养吸收）

■ 语文/历史：
  - 意境渲染动画（诗句逐句出现 → 对应画面渐入 → 氛围音效配合）
  - 历史事件时间线（年份标记 → 事件卡片逐一弹出 → 因果关系连线）
  - 地图演变（疆域变化 → 迁徙路线 → 贸易路线动态绘制）

■ 英语：
  - 对话情境演示（场景背景 → 人物出现 → 对话气泡逐句弹出 → 关键词高亮）
  - 语法结构可视化（句子拆解 → 成分标注 → 变换过程动画）

■ 地理：
  - 自然过程动画（板块运动 → 山脉隆起 → 火山/地震 → 地形变化）
  - 气候系统（气流运动 → 降水形成 → 季节变化 → 温度带分布）

【技术规范】
1. 分辨率 1920×1080，帧率 30fps
2. 配色必须与 HTML 课件的 CSS 变量保持统一（从 {课件配色} 提取）
3. 字体：中文使用 'Noto Sans SC'（必须安装），英文使用系统默认
4. 动画风格：使用 Remotion 的 `interpolate` + `spring` 实现平滑过渡，禁止生硬的瞬间切换
5. 文字元素：标题 ≤ 10 字，说明文字 ≤ 30 字，禁止大段文字堆砌

【三轨合一要求（⚠️ 强制）】
1. 画面轨：Remotion Composition 渲染的教学动画
2. TTS 语音轨：使用 edge-tts 为每个场景生成朗读语音，通过 `<Audio src={staticFile(...)}/>` 叠加
3. 音效/配乐轨：使用 generate-sfx.js 生成氛围音效，或使用合适的背景音乐
4. 最终 mp4 必须通过 ffprobe 验证含 audio 流：`ffprobe -show_entries stream=codec_type` 必须有 `audio`
5. 哑片（无音频轨的 mp4）= 不合规，Completeness Gate 直接不通过

【输出要求】
1. 创建 remotion/ 项目目录，编写 Composition 组件
2. 执行 `npx remotion render` 渲染 mp4
3. 将产出 mp4 复制到 {课件目录}/assets/video/ 下
4. 为每个视频生成合适的 poster 封面图（使用 image_gen 生成主题专属图，禁止复用 hero 图）
```

#### 降级策略

| 环境能力 | 策略 |
|:---|:---|
| 支持 `task` 工具 + 支持 `image_gen` + Node.js 可用 | 完整多 Agent 协作（A+B+C+D+R 并行） |
| 支持 `task` 工具 + 支持 `image_gen`，Node.js 不可用 | A+B+C+D 并行，R 降级需用户书面豁免 |
| 支持 `task` 工具，不支持 `image_gen` | A+B+D+R 并行，C 降级为占位符 |
| 不支持 `task` 工具 | 单 Agent 串行模式（按 Phase 顺序执行），在 Generation Gate 中标注"单 Agent 模式" |

**单 Agent 串行模式的执行顺序**：
```text
中文课件 → 英文课件 → 插图生成（如支持） → Remotion 动画渲染 → TTS 语音 → Completeness Gate → 打包
```
