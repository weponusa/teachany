## 十一、课件开发标准流程（强制检查点工作流）

> ⚠️ **铁律**：以下 Phase 0 → 0.5 → 1 → 2 → Generation Gate → 3 → Completeness Gate → 4 → Output Decision 是**串行强制流程**。
> 每个 Phase 末尾都有 `✅ 通过条件`，**未满足通过条件时禁止进入下一个 Phase**。
> 如果某个 Phase 的通过条件无法满足，必须在输出中明确标注跳过原因。

### Phase 0：确定对象与目标 ⛔ CHECKPOINT

必须完成以下全部项目：

1. **回答 6 问**（不可跳过，逐条列出答案）：
   - 学生是谁？（年级、基础水平）
   - 学什么？（具体知识点名称）
   - 为什么学？（课标要求 / 生活应用 / 后续课程需要）—— 如果 Phase 0.5 获取到了 `curriculum_standards` 字段，优先引用其中的课标依据来回答此问
   - 学到什么程度？（Bloom 层级目标）
   - 用什么方式学？（课型：新授 / 复习 / 专题 / 习题 / 实验）
   - 怎么知道学会了？（评估方式：前后测 / 产出任务 / 量规）

2. **明确学科与学段**：不可假设，必须显式确认。
3. **判断课型**：新授 / 复习 / 专题 / 习题 / 实验 / 项目制 / 跨学科融合 — 课型决定后续结构选择。
4. **选择驱动模式**：根据 Section 3.2-3.3 的决策树，选择问题驱动 / 项目驱动 / 活动驱动 / 问题链驱动。
5. **预判需求**：是否需要前测、是否需要动画（L2）、是否需要开放任务。AI 多模态互动区**默认需要**（仅纯计算/纯习题/纯复习课标注跳过理由）。
6. **L3 语音讲解**：**默认必选**。AI 必须为每个课件自动生成 TTS 语音讲解，除非用户明确说"不要语音/不要配音/不要TTS"。
7. **教材版本确认** ⭐ NEW：确定用户使用的课本版本，用于后续注入真实教材内容。

   **操作流程**：
   1. 读取 `references/data/editions/registry.json`
   2. 根据步骤 2 确定的学段+学科，查找该学科的版本信息
   3. **判断是否需要询问**：
      - `unified: true`（统编学科：语文、历史、道德与法治/思想政治）→ 自动使用"人教版"，**无需询问**
      - `unified: false`（多版本学科：数学、物理、化学、生物学、英语、地理等）→ **必须询问用户**
   4. **询问方式**（仅多版本学科）：
      ```
      📚 检测到该学科有多个教材版本，请确认您使用的课本版本：
      1. 人教版（默认）
      2. 北师大版
      3. 苏教版
      ...
      请输入序号或版本名称（直接回车使用默认版本）：
      ```
   5. **记录版本**：将确认的版本记录为 `textbook_edition` 变量，传递给 Phase 0.5
   6. **降级规则**：
      - 用户未回答 → 使用 `default_editions` 中的默认版本（通常为人教版）
      - `registry.json` 不存在 → 跳过教材注入，不阻断流程
      - 用户明确说"不需要课本内容" → 标注跳过，不阻断

8. **输出格式选择** ⭐ v5.34 新增：确定课件的最终交付格式。

   **默认规则**：仅输出 HTML 互动课件（`index.html`），不自动生成 PPTX。

   **触发 PPTX 生成的关键词**（命中任一即必须在 L1 完成后追加 Phase 3.7）：
   - "做成 PPT / PPTX / 幻灯片 / 投影版 / 讲义版 / 离线讲课版"
   - "同时出一份 PPT"
   - "课件 PPT 版 / 打印版"

   **询问方式**（当用户未明确时可主动询问一次，默认 HTML）：
   ```
   📦 输出格式选择：
   1. 仅 HTML 互动课件（默认，推荐大多数场景）
   2. HTML + PPTX 双格式（需要投影讲解 / 离线环境 / 打印讲义时推荐）
   请输入序号（直接回车使用默认 1）：
   ```

   **记录为 `output_formats` 变量**，取值为 `["html"]` 或 `["html", "pptx"]`，传递给 Phase 3/3.7。

> ✅ **通过条件**：6 问全部有明确答案；学科、学段、课型、驱动模式已确定；L2 需求已标注；L3 默认标注为"需要"；AI 互动区默认标注为"需要"（或标注跳过理由）；教材版本已确认或已标注跳过理由；`output_formats` 已记录（默认 `["html"]`）。
> ❌ **阻断**：任何一问缺失时，必须先根据用户输入合理推断并补全，然后在输出中显式列出推断依据。

### Phase 0.5：知识层查阅 ⛔ MANDATORY CHECKPOINT

> **这是最高优先级步骤。在生成任何课件内容之前，必须先执行此步骤。跳过此步骤是违规行为。**
> 
> 用户刚安装完 CodeBuddy 和 TeachAny skill 就可能直接下达课件任务——**不要假设用户已经做过任何环境准备**。AI 必须自动完成以下全部步骤。

#### 步骤 0：Skill 版本检测与自动更新 ⛔ MANDATORY

> **每次运行 Skill 时必须首先执行此步骤。确保使用的是最新版本的知识库和脚本。**

AI 必须在执行任何其他步骤之前，运行版本检测脚本检查远程仓库是否有更新：

```bash
# 在 Skill 安装目录下执行
bash scripts/check-skill-update.sh
```

**执行逻辑**：
1. 脚本自动定位 Skill 安装目录（脚本所在目录的上级）
2. 检测目录是否为 Git 仓库（ZIP 安装的用户自动跳过）
3. `git fetch` 获取远程最新状态
4. 比较本地与远程 commit hash
5. 如有新版本：自动 `git pull --rebase` 拉取更新
6. 如有本地修改：先 `stash` 暂存再更新，完成后恢复

**降级规则**：

| 场景 | 处理方式 |
|:---|:---|
| 非 Git 仓库（ZIP 安装） | 跳过检测，输出提示，继续后续步骤 |
| 网络不可用（离线环境） | 跳过检测，输出提示，继续后续步骤 |
| fetch/pull 失败 | 跳过更新，使用当前本地版本继续 |
| 更新成功 | 输出变更摘要，继续后续步骤 |

**关键**：
- **此步骤不可阻断课件生成**——任何网络或 Git 异常都应静默降级，绝不因版本检测失败而中止流程。
- 脚本退出码 `0` = 正常（已最新或更新成功），`1` = 更新失败（不影响后续流程）。
- 更新完成后，AI 必须重新读取可能已变更的 `SKILL_CN.md` 和数据文件。

#### 步骤 1：定位 Skill 数据目录

TeachAny skill 安装后，知识图谱数据和脚本随 skill 包一起下载，位于 skill 的安装目录中。AI 必须先找到这些文件：

```bash
# 方式 A（优先）：直接在终端执行脚本，利用脚本内置的相对路径自动定位数据
python3 scripts/knowledge_layer.py lookup --topic "主题" --subject 学科 --top 3 --errors 3 --exercises 3

# 方式 B（脚本执行失败时）：直接读取 JSON 文件
# 知识图谱数据结构：references/data/{subject}/{domain}/_graph.json / _errors.json / _exercises.json
# 浏览 data/ 目录，找到对应学科和领域的 JSON 文件，直接读取
```

**自动降级规则**（按优先级依次尝试，**每一级失败后必须继续尝试下一级，不可跳级**）：

| 优先级 | 方式 | 条件 | 操作 |
|:---|:---|:---|:---|
| 🥇 | 执行 `knowledge_layer.py` | Python 可用 + 脚本存在 | 直接执行，获取结构化摘要 |
| 🥈 | 直接读取 JSON 文件 | 脚本执行失败，但 `data/` 目录存在 | 用 `read_file` 工具读取 `references/data/{subject}/{domain}/_graph.json` 等文件 |
| 🥉 | Web 搜索补充 | 数据目录不存在或主题未覆盖 | **必须**使用 web_search 工具搜索"[学科] [知识点] 课标 前置知识 易错点 教学设计"，从搜索结果中提取定义、前置链、易错点等关键数据 |
| 🥊 | 模型知识兜底 | web 搜索也无法获取充分信息 | 依赖模型自身知识，但必须标注 ⚠️ 并在输出中说明"此内容未经图谱或搜索验证" |

**关键**：
- 无论走哪条路径，最终都必须获取到知识层数据（或明确确认"未命中"）。
- **不允许因为脚本执行失败就跳过整个 Phase 0.5**。
- **🥉 Web 搜索是必经步骤**，不允许跳过搜索直接用模型知识。只有搜索也无法获取时才降级到 🥊。

#### 步骤 2：执行知识层检索

示例命令：
- `python3 scripts/knowledge_layer.py lookup --topic "欧姆定律" --subject physics`
- `python3 scripts/knowledge_layer.py lookup --topic "一次函数" --subject math`
- `python3 scripts/knowledge_layer.py lookup --topic "光合作用" --subject biology`

如果脚本执行失败，按降级规则切换到方式 B：直接读取 JSON 文件。

#### 步骤 3：提取关键数据（命中时必须全部提取）

从 `_graph.json` 中提取：
- `definition`：精确定义 → 用于课件概念卡片
- `prerequisites`：前置知识链 → 用于前测设计和知识回顾模块
- `leads_to`：后续知识 → 用于"学了有什么用"模块
- `grade` / `semester` / `unit`：课标定位 → 用于校验 Phase 0 的年级判断
- `real_world`：真实场景 → 用于 ABT 引入和生活应用模块
- `curriculum_standards`：课标引用（可选字段）→ 结构化的课程标准引用，每条包含 `category`（类型标签：`core_competency` 核心素养 / `required_experiment` 必做实验 / `learning_task_group` 学习任务群 / `content_thread` 内容主线 / `cross_disciplinary` 跨学科实践 / `curriculum_change` 课标调整 / `teaching_requirement` 教学要求）和 `content`（原文）。**用途**：用于 Phase 0 第三问"为什么学"的课标依据、必做实验的教学设计、跨学科活动规划。**注意**：此字段是教师视角的教学设计参考，**不要**直接作为 ABT 场景展示给学生。
- `memory_anchors`：记忆锚点 → 用于助记和总结模块
- `bloom_verbs`：Bloom 行为动词 → 用于练习题设计

从 `_errors.json` 中提取：
- `description` / `diagnosis` / `trigger` / `frequency` → 用于设计针对性练习的干扰项和纠错反馈

从 `_exercises.json` 中提取：
- 与当前教学目标匹配的 `bloom_level` 题目 → 直接复用或改编进课件

#### 步骤 3.5：查阅教材补充数据（可选增强）⭐ NEW

> **这是质量提升步骤。在已获取知识图谱数据后，进一步查阅教材补充素材，用真实教材内容替代AI编造。**

**执行条件**：
- 步骤3已成功获取 `_graph.json` 数据
- 希望提升课件的真实性和教学性
- 对应学科存在教材补充数据

**操作流程**：

1. **检查教材补充数据是否存在**：
   ```bash
   # 检查是否有对应学科的教材补充目录
   ls references/data/textbook-supplements/{subject}/
   # 示例: ls references/data/textbook-supplements/math/
   #       ls references/data/textbook-supplements/biology/
   ```

2. **根据当前节点ID，读取相关素材文件**：
   
   可用的数据文件类型：
   - `teaching_methods.json` → 教学方法(如双栏解法、Visual Connection思考题)
   - `real_world_scenarios.json` 或 `phenomena_library.json` → 真实场景/日常现象
   - `analogies.json` → 类比隐喻/记忆锚点
   - `visual_strategies.json` → 可视化策略/图表设计
   - `experiment_designs.json` → 实验设计方案(理科)
   - `ecological_cases.json` → 生态学案例(生物学特有)
   
   示例：
   ```python
   # 读取数学学科的真实场景
   scenarios = read_json("references/data/textbook-supplements/math/real_world_scenarios.json")
   
   # 读取物理学科的日常现象
   phenomena = read_json("references/data/textbook-supplements/physics/phenomena_library.json")
   
   # 读取生物学科的教学方法
   methods = read_json("references/data/textbook-supplements/biology/teaching_methods.json")
   ```

3. **筛选匹配当前节点的数据**：
   ```python
   # 从教材数据中筛选适用于当前节点的内容
   current_node_id = "linear-function"  # 示例：一次函数
   
   relevant_items = [
       item for item in data["items"] 
       if current_node_id in item.get("applicable_node_ids", [])
   ]
   ```

4. **优先使用教材素材替代AI生成内容**：
   
   | 课件模块 | 优先使用的教材数据 | 降级方案 |
   |:---|:---|:---|
   | ABT引入场景 | `real_world_scenarios` / `phenomena_library` | `_graph.json` 的 `real_world` 字段 |
   | 记忆锚点/类比 | `analogies.json` | `_graph.json` 的 `memory_anchors` 字段 |
   | 实验设计 | `experiment_designs.json` | AI设计实验方案 |
   | 可视化设计 | `visual_strategies.json` 的描述 | AI生成可视化方案 |
   | 教学方法 | `teaching_methods.json` 的 `implementation_notes` | 通用教学方法 |
   | 生态案例(生物) | `ecological_cases.json` | `real_world_scenarios` |

5. **标注数据来源**：
   - 如果使用了教材素材，在课件中标注来源：`💡 来源: [教材名称] [章节]`
   - 在Phase 0.5输出中说明：`✅ 已引用教材补充数据（X条）`
   - 如果未命中教材数据，继续使用 `_graph.json` 数据（不强制要求教材数据）

**数据优先级（降级规则）**：

| 优先级 | 数据来源 | 适用场景 | 示例 |
|:---|:---|:---|:---|
| 🥇 | 教材补充数据 | 有精确匹配的node_id | 上海磁悬浮列车案例(College Algebra Ch1) |
| 🥈 | 知识图谱数据 | 教材数据未命中 | `_graph.json` 中的 `real_world` 字段 |
| 🥉 | Web搜索 | 图谱数据不充分 | 搜索"一次函数 生活应用 案例" |
| 🥊 | 模型知识 | 所有数据源都不充分 | AI编造案例(必须标注⚠️) |

**关键原则**：
- ✅ **真实性优先**：教材中的真实案例 > AI编造的虚构案例
- ✅ **补充增强**：教材数据用于补充图谱，不替代图谱核心数据(如定义、前置知识链)
- ✅ **冲突处理**：如果教材数据与图谱数据冲突，以图谱数据为准(图谱经过课标校验)
- ✅ **可选性**：此步骤是增强项，未命中教材数据不阻断流程

**输出示例**：

```
✅ Phase 0.5 完成
- 知识图谱命中: linear-function (一次函数)
- 教材补充数据:
  • 真实场景: 上海磁悬浮列车距离函数 (OpenStax College Algebra Ch1, p.45)
  • 类比隐喻: 斜率=爬楼梯陡度 (OpenStax Prealgebra 2e Ch3, p.320)
  • 可视化策略: 四象限多表征法 (Prealgebra 2e Ch4)
- 数据来源优先级: 🥇教材数据(3条) + 🥈图谱数据
```

#### 步骤 3.6：中国教材内容注入（可选增强）⭐ NEW v5.15

> **根据用户在 Phase 0 确认的教材版本，从开源 ChinaTextbook 仓库获取对应课本 PDF，解析后注入课件制作流程。用真实课本内容替代AI编造的例题和情境。**

**数据来源**：[ChinaTextbook](https://github.com/TapXWorld/ChinaTextbook)（⭐ 69.6k），包含小学/初中/高中全学段、全学科、多版本教材 PDF。

**执行条件**：
- Phase 0 第 7 步已确认 `textbook_edition`（教材版本）
- 当前学科为 K12 中国课程（非英文原版教材场景）
- `registry.json` 存在且可读

**操作流程**：

1. **读取注册表，拼接仓库 URL**：
   ```python
   import json
   registry = read_json("references/data/editions/registry.json")
   
   # 示例：初中数学，人教版
   stage = "初中"          # 来自 Phase 0 学段
   subject = "数学"        # 来自 Phase 0 学科
   edition = "人教版"      # 来自 Phase 0 第7步
   
   # 拼接浏览 URL
   base_url = registry["_meta"]["base_url"]
   browse_url = f"{base_url}/{stage}/{subject}/{edition}"
   # → https://github.com/TapXWorld/ChinaTextbook/tree/master/初中/数学/人教版
   ```

2. **获取教材目录（用 web_fetch）**：
   ```python
   # 获取该版本下的年级/册次列表
   directory = web_fetch(browse_url)
   # 返回示例: 七年级上册/, 七年级下册/, 八年级上册/, ...
   ```

3. **定位对应册次**：
   - 根据 Phase 0 确定的年级（如"八年级"）和知识点所在章节
   - 选择对应的册次目录（如"八年级上册"）
   - 获取该目录下的 PDF 文件名

4. **获取教材 PDF 内容**：
   
   **方式 A（推荐）：使用 MinerU API 解析 PDF**：
   ```bash
   # 拼接 PDF 的 raw URL
   raw_url="https://raw.githubusercontent.com/TapXWorld/ChinaTextbook/master/初中/数学/人教版/八年级上册/八年级上册.pdf"
   
   # 调用 MinerU API 解析 PDF 为结构化文本
   # MinerU Token: 见用户配置
   curl -X POST "https://mineru.net/api/v4/file-urls/batch" \
     -H "Content-Type: application/json" \
     -H "Authorization: Bearer {MINERU_TOKEN}" \
     -d '{"file_urls": ["'$raw_url'"], "is_ocr": true}'
   ```
   
   **方式 B（降级）：使用 web_fetch 获取文本**：
   ```python
   # 如果 MinerU 不可用，尝试直接 web_fetch PDF URL
   # 注意: 效果可能不如 MinerU
   content = web_fetch(raw_url, "提取教材中关于{知识点}的章节内容、例题和练习题")
   ```

5. **提取与当前知识点相关的内容**：
   - 从解析结果中定位对应章节（如"第十四章 一次函数"）
   - 提取以下内容：
     - 📖 **章节引入情境**：课本开篇的真实情境/问题
     - 📝 **例题与解答**：课本原题（含完整解题过程）
     - 🎯 **练习题**：课后练习题（可用于课件练习模块）
     - 💡 **探究活动**：课本中的探究/思考环节
     - 📊 **图表数据**：课本中的统计图表、函数图像描述

6. **注入课件制作流程**：
   
   | 课件模块 | 注入的教材内容 | 注入方式 |

**步骤 3.0 媒体选型决策（⛔ 必做，在动手写代码之前）**：

> 📌 **核心原则：不盲目套模板，先想清楚再动手。** 每个媒体模块（Canvas 互动、Remotion 动画、地图、TTS 音频、生图）的选择，必须基于**学段认知特征**和**知识点本质**来决策，而不是无脑把基线清单的每一项都塞进课件。

在为每个知识模块选择媒体形式时，按以下框架决策：

**1. 按学段认知特征选型**

| 学段 | 认知特征 | Canvas 互动选型 | Remotion 动画选型 | 地图/空间模块 | TTS/音频选型 |
|:---|:---|:---|:---|:---|:---|
| **小学** G1-6 | 具体形象思维，注意力短，需即时反馈 | 简单拖拽/涂色/配对，大按钮，动画反馈 | 短片段（5-15秒），卡通风格，强节奏感 | 简单标注地图，大字体，颜色区分 | 语速慢，语气亲切，每段<30秒 |
| **初中** G7-9 | 过渡到抽象思维，需要"桥梁"（具体→抽象） | 参数调节/分步操作/实时绘图，有明确目标 | 中等长度（15-30秒），半写实风格 | 互动地图，可点击查看详情，图例说明 | 语速适中，结构化讲解，每段45-90秒 |
| **高中** G10-12 | 抽象逻辑思维，需要深度分析和比较 | 复杂模拟/数据可视化/多变量控制 | 较长片段（30-60秒），学术风格，数据驱动 | 多图层叠加对比，GeoJSON 边界叠加分析 | 语速偏快，论证式讲解，可长至2分钟 |

**2. 按知识点本质选型**

| 知识点类型 | 首选媒体 | 为什么 | 典型场景 |
|:---|:---|:---|---|
| **过程性变化**（函数图像变换、化学反应、生物分裂） | **Remotion 动画** | 必须展示"从 A 到 B"的连续过程，静止截图无法传达 | 二次函数开口/平移、有丝分裂过程、铁生锈 |
| **可交互探索**（参数影响、几何变换、电路连接） | **Canvas 互动** | 学生需要自己操作参数，观察"如果改了X会怎样" | 滑块调 k/b 看直线变化、拖拽三角形看内角和、调电阻看电流 |
| **空间分布**（地理区域、历史疆域、迁徙路线） | **Leaflet 地图** | 必须在空间维度上呈现，非空间媒体无法替代 | 季风区分布、秦朝疆域、红军长征路线 |
| **时序关系**（朝代更替、实验步骤、历史事件链） | **时间轴/排序互动** | 时序是核心理解维度 | 朝代顺序、实验步骤排序、事件因果链 |
| **结构/层级**（原子结构、政治体制、文章结构） | **SVG/Canvas 标注图** | 需要展示层级嵌套关系 | 原子电子层、唐朝三省六部、议论文三段式 |
| **情感/意境**（古诗意境、历史情境、文学场景） | **AI 生图 + TTS 朗读** | 视觉+听觉双通道构建沉浸感 | 《静夜思》月夜意境、赤壁之战火攻场景 |
| **纯计算/推导**（方程求解、几何证明、化学配平） | **分步交互** | 需要学生跟着步骤走，而非被动看 | 解一元一次方程、三角形全等证明、化学方程配平 |

**3. 选型决策检查清单（每个模块必须过一遍）**

```
□ 这个知识点，学生最需要理解的是什么？（过程？空间？结构？关系？）
□ 用什么媒体形式最能帮助理解？（对照上面的知识点本质表）
□ 这个学段的学生能看懂/操作这个交互吗？（对照学段认知表）
□ 有没有更简单的方案能达到同样的教学效果？（避免过度工程化）
□ 基线清单的每一项，在这个模块里是"加分"还是"凑数"？（凑数的不做）
```

> - 小学数学"20 以内加减法"搞了个 3D 模拟器 → 认知负荷过高，简单点数/拖拽卡片更合适
> - 高中历史"辛亥革命"只放文字没有地图 → 空间维度缺失，必须加历史地图展示势力范围
